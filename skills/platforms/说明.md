# 平台运营 Skills

这里放 **Platform Skills**：某个社交 / 开发者平台上的身份、发帖、（未来）回复与私信。

与 **Investment Skills**（`skills/技能模板.md`）严格分开：

| 类型 | 回答的问题 | 模板 |
|---|---|---|
| Investment Skill | 投资判断怎么做、Evidence 是什么 | `skills/技能模板.md` |
| Platform Skill | 在这个平台怎么改资料、怎么发、字数/坑是什么 | `skills/platforms/_模板.md` |

文案唯一源：[`内容/品牌/身份统一包.md`](../../内容/品牌/身份统一包.md)  
平台只写差异；不复制第二套简介。

Cursor 发现：`.cursor/skills/platform-*` 为薄包装，正文以本目录为准。

## 新加入流程

Founder **明确授权**开通某平台后，按此顺序执行（不为未开通平台预建）：

```text
1. Founder 明确授权开通（不为未开通平台预建）
2. 复制模板 → 写平台差异 → Cursor 薄包装镜像
3. 更新索引：本说明、skills/说明.md、身份包映射、增长.md 账本
4. 同步基础信息（显示名 / 简介 / 网站 / 头像）→ 回写 Evidence
5. 询问：是否把已有公开文章同步到该站
6. 是 → 按该站语气/字数从已有草稿裁切发布 → 记公开 URL
7. 否 → 停
8. WebBridge close_session
```

第 4 步的昵称 / 显示名：若改名有冷却、金币或降权成本，**先问 Founder**，不得默认强改。

第 5 步必须口头确认后才发帖；不得自动发布。

## 公共规则

1. 操作默认用 Kimi WebBridge；遵守 `.cursor/rules/kimi-webbridge.mdc`（**用完关闭**）
2. 公开链路：社交主页 → `https://github.com/grlib` → `https://github.com/grlib/alphaforge`
3. 禁止 `mian45.com`、荐股话术
4. Reply / DM 各 Skill 内为空壳，有真实互动量再实现

## 不做

- 不为未开通的平台预建 Skill（即刻 / 公众号 / 小红书 / B 站）
- 不在 Platform Skill 里发明新定位文案
