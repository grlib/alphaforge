# Day 2：用 WebBridge 把五个平台收成可复用 Skill

## 总结昨日

昨天把公开入口打通了：GitHub 主页和仓库、雪球、知乎、X，并发了第一篇——为什么把旧的 AI 股票系统推倒重来，以及 AlphaForge 在验证什么。

当时各站简介还不统一，改资料、发帖是一次性手工。Agent 下次再去，还得重新摸每个站的坑。

## 今天做什么

把「我是谁」收成一份身份统一包，再给每个已开通平台做成独立 Skill。

Skill 先覆盖两件事：**改基础信息**（显示名、简介、网站、头像路径），以及 **发文**。回复评论、处理私信先留空壳——等有真实互动再做。今天是在为后续各平台 Agent 做准备，而不是再写一篇只能用一次的操作备忘。

同时按同一套「新加入流程」开通集思录：先同步基础信息，再决定是否把已有文章同步过去。

## 使用什么工具

- **Kimi WebBridge**：用本机真实浏览器登录态改资料、发帖、核对每个站的字数和坑。用完关闭，避免窗口堆满。
- **Cursor**：把身份包和 Skill 写进仓库，让下次加载即可执行。
- **GitHub MCP**：核对并更新公开仓库 / Profile。

没有新造浏览器，也没有新造发帖后台。WebBridge 已经能碰真实登录态；缺的是「每个站怎么做」的可复用 Skill。

## 今天造什么工具

1. **身份统一包**：国内中文、国外英文；主名 AlphaForge Founder；文案只此一处，各站引用，不另编故事。
2. **Platform Skills v1**（五个）：GitHub / X / 雪球 / 知乎 / 集思录。每个 Skill 写清：账号、字数、改名规则、怎么改资料、怎么发文、WebBridge 怎么操作、已知坑。
3. **新加入流程**：授权开通 → 写 Skill → 同步基础信息 → 再问是否同步已有文章 → 用完关浏览器。
4. 集思录昵称不改（改名耗金币、会降权新人）。签名和头像被「活跃用户」锁住，记进 Skill，不假装已同步。

这些是分发侧工具，不是投资 Skill。投资方法怎么变成 Agent，还没开始造。

## 得到什么结果 + 对外发布

已落地：

- 5 个平台 Skill 可以按站加载：改资料、发文。
- 集思录已开通，上一篇已发在该站。
- GitHub、X 的显示名 / Bio / Website 已按身份包同步；知乎简介已同步。

还没过的墙：

- 头像自动化上传：Chrome 一律 Not allowed，五站头像仍待人工。
- 集思录普通用户不能改签名、不能接头像。
- 知乎改名规则卡住目标显示名。
- 雪球站点间歇打不开，简介同步未完成。
