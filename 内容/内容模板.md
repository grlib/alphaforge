## Canonical（GitHub Build Log 源）

对外发布的**唯一事实源**。五段结构；**不写「明天做什么」**；不写「不是荐股」「N 天」。

### 1. 总结昨日

昨天公开了什么、验证了什么。用具体 URL / 数字。

### 2. 今天做什么

今天要测的 Hypothesis 与动作（一件事为主）。

### 3. 用了什么工具

Used Tools（已有工具）：名称 + 用来干什么。

### 4. 造了什么工具

Built Tools（仓库新增可复用能力）：Skill / 规则 / 脚本。没有则写「无」。

### 5. 结果 + 发布

- 做成了什么（Evidence）
- 失败墙（真实 blocker）
- 仓库 / 主页链接
- **一个**可回答的问题（给读者）

### 插图（Canonical 可选）

本地路径写进草稿；各站按裁切规格决定是否上传。不要只贴 raw.githubusercontent 链接当正文图。

一句话判断 + 1–2 个数字。供 X 钩子帖 / 雪球短引子。

## 各站裁切规格

先写 Canonical，再按站裁切。**禁止**把 `/end-day` 章节名（总结昨日 / 今天做什么…）原样当对外标题。

共同点：具体数字、真实失败、一个可回答的问题。学热门结构，不攀比盐选 8 千–1.5 万字。

### 知乎（专栏叙事）

| 项 | 规格 |
|---|---|
| 形态 | 失败/反常识钩子 → 判断句 H2 → 证据 → 引用块失败墙 → 提问 |
| 字数 | 约 **1500–3000**；发布门禁：编辑器底部字数 **> 800** |
| 标题 | 判断句 / 反差，不用五段日志标题 |
| 开篇 | **200 字内**钩子 |
| 图 | 每 3–4 段一图或引用；工具栏「图片」本地上传（自动化常 Not allowed） |
| 入口 | 优先工具栏 **导入** Markdown；失败再按段 `insertText`；**禁止一次 `fill` 整篇** |
| 发后核对 | 打开**无** `/edit` 的公开 URL：须含第一节判断 + GitHub 双链；截断则撤回重来 |

### 雪球（长文）

| 项 | 规格 |
|---|---|
| 形态 | **一个判断** + **2–4 个数字** + 图 + 提问 |
| 入口 | 点首页 / 创作入口的 **「长文」**；**不要**用首页短框（已验证写不进） |
| 篇幅 | 不宜过长；忌情绪帖、忌荐股 |
| 发后核对 | 公开帖含判断句、数字、仓库链接 |

参考：[雪球运营指南](https://xueqiu.com/operation/guide)

### 集思录（问题帖）

| 项 | 规格 |
|---|---|
| 标题 | **问题句** |
| 正文 | 重数据、重逻辑、轻结论；代码块列数字和失败墙；结尾要**步骤**不要口号 |
| 图 | 新人主贴通常无图 |
| 发后核对 | 公开帖像真实问题，不像产品发布 |

### X（Thread）

| 项 | 规格 |
|---|---|
| 形态 | 钩子帖 + **5–8** 条 thread；**一条一个点** |
| 顺序 | 钩子 → 昨日 → Skill/动作 → 工具 → 墙 → GitHub |
| 禁忌 | 不要单条 200+ 字墙 |
| 发后核对 | 线程每条可独立读懂；含失败点与仓库链接 |

### GitHub（Canonical 原样）

| 项 | 规格 |
|---|---|
| 形态 | 保留五段 Build Log；可配表 / 图 |
| 入口 | 仓库文件或 Profile README 链到最新一期 |
| 发后核对 | README / 文件可点进仓库；链接有效 |
